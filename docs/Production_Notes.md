# Production Notes: TrainSight Data Pipelines & Validation

## 1. Overview

**TrainSight** serves as the deterministic pre-flight data inspector and real-time data validator within **AetherControl**. Its core mission is to eliminate GPU compute waste, CUDA Out-Of-Memory (OOM) failures, and gradient divergence *before* training or fine-tuning workloads hit expensive hardware clusters.

---

## 2. Production Dataset Schemas

In production LLM post-training pipelines, TrainSight standardizes and validates three primary data schemas:

### A. Supervised Fine-Tuning (SFT) – Multi-Turn Chat Format
*(Used by datasets like UltraChat, ShareGPT, OpenHermes)*
```json
{
  "messages": [
    {"role": "system", "content": "You are a senior LLM infrastructure engineer specializing in vLLM dynamic batching."},
    {"role": "user", "content": "How do I calculate KV-cache memory usage for a Llama-3-70B model?"},
    {"role": "assistant", "content": "To calculate the KV-cache footprint per token: 2 * num_layers * num_kv_heads * head_dim * precision_bytes..."}
  ]
}
```

### B. Direct Preference Optimization (DPO) – Pairwise Feedback
*(Used by datasets like UltraFeedback, Anthropic HH-RLHF)*
```json
{
  "prompt": "Explain gradient clipping in PyTorch.",
  "chosen": "Gradient clipping caps total gradients at a max norm (`torch.nn.utils.clip_grad_norm_`) to prevent exploding gradients during backpropagation.",
  "rejected": "Gradient clipping makes your neural network run much faster by skipping bad layers."
}
```

### C. Group Relative Policy Optimization (GRPO / DeepSeek R1 Style) – Math & Coding Reasoning
*(Used by datasets like GSM8K, MATH, LiveCodeBench)*
```json
{
  "problem": "Solve for x: 3x + 5 = 20",
  "expected_answer": "5",
  "verification_type": "math_exact_match",
  "reward_function": "sympy_eval"
}
```

### D. Supported Industry Production Datasets

| Dataset | Use Case | Size | Source |

## 3. Real-Time Ingestion Architecture

In production LLM infrastructure, TrainSight operates across two real-time execution models:

```
[ Synthetic Generator (vLLM) / Label Studio ] 
                  │
                  ▼ (Kafka Stream / S3 Events)
         [ TrainSight Inspector ] 
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
   [ Valid Data ]      [ Rejected / Quarantined ]
  (Pushed to DB)     (Logged with OOM/Duplicate Alert)
```

### 1. Kubernetes Pre-Flight InitContainer Guard & Fail-Fast Mechanism
* **Fail-Fast Execution:** Runs `trainsight profile --dataset /data/dataset.jsonl --type sft --strict`. If any corrupt completion, empty entry, or OOM risk is detected, `trainsight` exits with `code=1` (`sys.exit(1)`).
* **K8s Protection:** Exit code 1 halts the K8s Pod initialization step **before** expensive GPU containers (`vllm-container` / `torchrun`) schedule or reserve VRAM resources.

### 2. Shift-Left CI/CD Pipeline Integration
* Integrated into GitHub Actions ([.github/workflows/ci.yml](file:///Users/aravindsundaresan/Development/LLM_Serving_Platform/.github/workflows/ci.yml)).
* Automatically executes dataset profiling on every git push / pull request, failing the CI build if dataset quality checks fail.

### 3. Data Versioning & Reproducibility (DVC)
* Tracked via Data Version Control ([dvc.yaml](file:///Users/aravindsundaresan/Development/LLM_Serving_Platform/trainsight/dvc.yaml)).
* InitContainers pull specific SHA256 dataset version hashes (`dvc pull`) to guarantee 100% reproducible data loads across training runs.

### 4. Streaming Ingestion Pipeline
* Scans incoming synthetic data generated by batch vLLM inference or human labelers prior to feature store registration.

## 4. Key Validation Metrics

| Metric | Target / Threshold | Action on Violation |
| :--- | :--- | :--- |
| **Max Sequence Length** | $\le$ Model Max Context | Truncate or filter to avoid CUDA OOM |
| **Sequence Variance ($\sigma$)** | $\le 0.75 \times \mu$ | Group into sequence length buckets |
| **Empty Completions** | 0 | Drop sample immediately |
| **Duplicate Prompts** | 0% | Deduplicate to prevent over-fitting |

## 5. Next Focus: vLLM Serving & Control Plane Integration

As we transition into `vllm-engine`, TrainSight validation metrics directly inform the vLLM serving configuration:
* **Token Distribution ($p_{95}, p_{99}$):** Informs `max_model_len` and KV-cache allocation ratios (`gpu_memory_utilization`).
* **Sequence Length Buckets:** Informs dynamic batching, continuous batching parameters, and PagedAttention block sizes.
